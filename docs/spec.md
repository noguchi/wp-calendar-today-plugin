# wp-calendar-today-plugin 表示仕様

`wp-calendar-today-plugin` は、カレンダープラグイン「Event Calendar Maker（無料版）」（以下、カレンダープラグイン）に登録した今日の予定を、ショートコード `[today_schedule]` でバッジとして表示する。
この文書は、前身の PoC（`top-schedule`）の表示仕様から今日の予定に関わる部分だけを引き継ぎ、書き直したものである。
PoC から変えた項目には、その理由を書く。

PoC にあった直近の予定一覧（`[top_schedule]`）と、それに付随する表示範囲の計算は対象外とした。
このプラグインが表示するのは今日の 1 日分だけであり、複数の月にまたがる取得と範囲の絞り込みは要らないためである。

## REST 応答の前提

仕様の前提となるカレンダープラグインの REST 応答の形は、作業指示（`docs/build-prompt.md`）の「カレンダープラグインの既知の情報」と、実例 `docs/api-samples/` に従う。
このプラグインが読むのは、その月の要素のうち今日の 1 要素と、その中の次の値だけである。

- **`date`**：`YYYY-MM-DD` の日付。
- **`holiday`**：祝日でない日は空配列、祝日は祝日名の文字列。
- **`events`**：予定の配列。各要素の `event_name`（予定名）、`event_description`（説明）、`link_text`（リンク URL）を使う。

## 呼び出し形式

```
[today_schedule hash="<hash>" link="/calendar/"]
```

- **hash**：カレンダーのフィールド名。`sanitize_text_field()` で整える。既定値は空で、空のときは「hash の未指定」として扱う（「管理者向けの表示」の節）。
- **link**：バッジのリンク先。`esc_url_raw()` で整え、空になったらリンクにしない。サイト内のパス（`/calendar/`）も書ける。
- **limit**：バッジに並べる予定の最大件数。`absint()` で整える。既定値は 0 で、0 のときは全件を並べる。数値でない値は 0 になる。

開始タグと終了タグの間に HTML を書くと、組み込みのテンプレートの代わりに、その HTML をテンプレートとして使う（「テンプレート」の節）。

PoC からの変更点は、ショートコードの名前である。
PoC では一覧が `[top_schedule]`、バッジが `[top_schedule_today]` だったが、このプラグインにはバッジしかないので `[today_schedule]` の 1 つにした。

## 組み込みのテンプレート

終了タグの間が空のとき（判定は「テンプレートの判定」の節）は、プラグインが持つ組み込みのテンプレートで出力する。
組み込みのテンプレートは、利用者が書くテンプレートと同じプレースホルダーと区間で書かれた HTML であり、同じテンプレートエンジンで埋める。
PoC では既定のバッジを固定の HTML として別に組み立てていたが、描画の経路を 1 つにして、コードとテストを減らすために変えた。

表示は次のとおりである。

```
9/27（日）
[開館日] 10:00 – 18:00
[庭園のみ開館]
ほか 1 件
```

- **日付と曜日**：`9/19（土）` の形（月と日にゼロ埋めをしない）。今日はサイトのタイムゾーンで決める。曜日は REST の `day_of_week` を使わず、今日の日付からサイトのタイムゾーンで求める。
- **祝日**：曜日に「祝」を付けて `9/21（月・祝）` とする。祝日名は出さない。REST の `holiday` が空でない文字列の日を祝日とみなす。カレンダーの「祝日・休日表示」の設定（`is_holiday`）は見ない。無料版ではこの設定を「表示する」に変えられず、見ると祝日を出せなくなるためである。
- **今日の予定**：予定を 1 件 1 行で並べる。`limit` を指定したときは最大 `limit` 件で、超えた分は「ほか N 件」とまとめる。1 行は、予定名のラベルと説明の順である。
- **ラベル**：予定名を、カレンダープラグインで付けたラベルの色（`{event_color}`）のクラスを持つ `<span>` で出す。色ごとの見た目はプラグインの CSS が持ち、無料版の `red`、`blue`、`green` はカレンダー本体のラベルと同じ色にする。それ以外の色名は既定の見た目（白地に灰色の枠）になる。
- **説明**：ラベルの後ろに、説明を登録した文字のまま出す。説明が空の予定では要素が空になるので、CSS の `:empty` で隠す。
- **予定が 0 件**：日付だけを出す。「予定はありません」とは書かない。予定のない日のほうが多いので、毎日「ありません」と出るのを避ける。
- **予定ごとのリンク**：出さない。バッジ全体が 1 つのリンクであり、リンクの中にリンクを入れることは HTML で禁止されているためである。

HTML は次の形である。

```html
<div class="wp-calendar-today">
  <a class="wp-calendar-today__badge" href="/calendar/">
    <time class="wp-calendar-today__date" datetime="2026-09-27">9/27<span class="wp-calendar-today__dow">（日）</span></time>
    <ul class="wp-calendar-today__events">
      <li class="wp-calendar-today__event"><span class="wp-calendar-today__label wp-calendar-today__label--blue">開館日</span><span class="wp-calendar-today__desc">10:00 – 18:00</span></li>
      <li class="wp-calendar-today__event"><span class="wp-calendar-today__label wp-calendar-today__label--green">庭園のみ開館</span><span class="wp-calendar-today__desc"></span></li>
    </ul>
    <span class="wp-calendar-today__more">ほか 1 件</span>
  </a>
</div>
```

- **外枠**：バッジは中身の幅に合わせたインライン要素にし、外側をブロック要素（`wp-calendar-today`）で包む。ブロックテーマの本文は、直下のブロック要素を本文の列に揃えるが、インライン要素は揃えないためである。
- **`link` が空**：`<a>` の代わりに `<div class="wp-calendar-today__badge">` で出力する。組み込みのテンプレートは `link` の有無で外枠だけが違う 2 つの文字列であり、`href` の値はテンプレートを選ぶときに `esc_url()` を通して埋める。
- **予定が 0 件**：`<ul>` を出力しない。
- **「ほか N 件」**：超えた分があるときだけ出力する。

PoC からの変更点は 4 つある。
見出し「本日の予定」は出さない。日付と予定が並べば何の表示かは分かり、見出しの分だけバッジが縦に長くなるためである。
クラス名の接頭辞を `top-schedule-badge` からプラグイン名に合わせた `wp-calendar-today` に変えた。
見出しのアイコン（`<svg>`）は出力しない。
組み込みのテンプレートを利用者のテンプレートと同じ経路で扱うにあたり、テンプレート文字列を短く保つためで、アイコンが要る場合は CSS の `::before` で付ける。
予定ごとにラベルの色と説明を出すようにした。
予定名を状態（開館日、休館日など）、説明を開館時間として登録する使い方で、複数の予定がある日にも状態と時間が並ぶようにするためである。

## テンプレート

日付や予定名を利用者が自分のデザインに組み込めるように、バッジの HTML をテンプレートに差し替えられる。
テンプレートは、`[today_schedule]` を終了タグのある形で書き、開始タグと終了タグの間に置く HTML である。
プラグインは、テンプレートの中の `{year}` のようなプレースホルダーを今日の値で埋めて出力する。

### 呼び出し形式と属性

```
[today_schedule hash="<hash>" limit="2"]
テンプレート（HTML）
[/today_schedule]
```

- **hash**、**limit**：組み込みのテンプレートと同じ。`limit` を指定すると `{events}` の区間の繰り返し回数の上限になる。
- **link**：使わない。リンクをどこに付けるか（バッジ全体、予定ごと、付けない）はテンプレートを書く人が決めるので、リンク先もテンプレートの中に直接書く。URL を属性とテンプレートの 2 か所に分けない。

### テンプレートの判定

開始タグと終了タグの間から、前後の空白と `<p>`、`</p>`、`<br>`（`<br />` を含む）を除いて空でなければ、テンプレートで出力する。
空なら組み込みのテンプレートで出力する。
終了タグのない書き方、`[today_schedule …][/today_schedule]`、空白だけを挟んだ書き方がこれにあたる。
`<p>` と `<br>` を空白とみなすのは、「ショートコード」ブロックとクラシックエディタでは、ショートコードより前に `wpautop()` が改行を `<br />` や `</p><p>` に変えるためである。

### テンプレートを置く場所

テンプレートは「カスタム HTML」ブロックに書く。
「ショートコード」ブロックは中身に `wpautop()` をかけるので、複数行のテンプレートに `<p>` と `<br>` が入り、HTML が崩れる。
ブロックを使わない本文（クラシックエディタ）でも、ショートコードより前に `wpautop()` が走るので同じことが起きる。
「カスタム HTML」ブロックの中身には `wpautop()` がかからない。

同じページで、終了タグのない `[today_schedule …]` をテンプレートより前に置く場合は、`[today_schedule … /]` と `/` を付けて書く。
WordPress は、終了タグのない開始タグの後ろに同じ名前の終了タグがあると、そこまでを中身として読むためである。

### プレースホルダー

プレースホルダーは、名前を波括弧で囲んだ `{name}` の形とする。
名前は英小文字と `_` からなる。

テンプレートのどこにでも書けるプレースホルダーは次のとおりである。
値はすべて、サイトのタイムゾーンで決めた今日のものである。

| プレースホルダー | 値 | 9/19 の値 |
| --- | --- | --- |
| `{year}` | 年 | `2026` |
| `{month}` | 月（ゼロ埋めなし） | `9` |
| `{day}` | 日（ゼロ埋めなし） | `19` |
| `{month_padded}` | 月（2 桁にゼロ埋め） | `09` |
| `{day_padded}` | 日（2 桁にゼロ埋め） | `19` |
| `{weekday}` | 曜日（漢字 1 字） | `土` |
| `{weekday_en}` | 曜日（英語の 3 文字の略称） | `Sat` |
| `{date}` | `YYYY-MM-DD` の形の日付。`<time>` の `datetime` 属性に使う | `2026-09-19` |
| `{holiday_name}` | 祝日名。祝日でなければ空 | 空（9/21 なら `敬老の日`） |
| `{event_count}` | 今日の予定の件数（`limit` で絞る前） | `1` |
| `{more_count}` | `limit` を超えた件数。超えなければ `0`。`limit` が 0 なら常に `0` | `0` |

- **ゼロ埋めと英語の曜日**：`09.19 SAT` のような表記に使う。大文字にするには CSS の `text-transform` を使う。
- **曜日**：`{weekday}` には「祝」を付けない。組み込みのテンプレートと同じ `（月・祝）` の形にするには、`（{weekday}{holiday}・祝{/holiday}）` と書く。
- **祝日**：組み込みのテンプレートと同じく、REST の `holiday` が空でない文字列の日を祝日とみなし、その文字列を祝日名とする。

`{events}` の区間の中では、次のプレースホルダーも書ける。
値は、繰り返しのその回の予定のものである。

| プレースホルダー | 値 | 例 |
| --- | --- | --- |
| `{event_name}` | 予定名 | `休館日` |
| `{event_description}` | 説明。なければ空 | 空 |
| `{event_url}` | リンク URL。`link_text` が http か https の URL でなければ空 | `https://www.yahoo.co.jp` |
| `{event_link}` | URL があれば予定名をそのリンクにした `<a>` 要素、なければ予定名だけ | `<a href="https://www.yahoo.co.jp">休館日</a>` |
| `{event_color}` | ラベルの色の名前。CSS のクラス名に使える文字（英小文字、数字、`-`、`_`）だけからなる。それ以外の値は空 | `green` |

- **予定名のリンク**：URL のない予定で `<a href="{event_url}">` と書くと、`href=""`（今のページへのリンク）になる。これを避けるために `{event_link}` を用意する。
- **説明**：カレンダープラグインには時刻の項目がないので、開館時間のように予定名に添えて出したい文字列は、説明に登録する。プラグインは説明を解釈せず、`esc_html()` を通した文字列をそのまま `{event_description}` に埋める。「10:00 – 18:00」と登録すれば、その文字が出る。時刻として解析したり、書式を整えたり、現在時刻と比べたりはしない。前後の空白だけを除く。
- **予定の色**：カレンダープラグインで予定に付けた「イベントラベルの色」を、REST の `color` が色の名前で返す。無料版で確かめた値は `red`、`blue`、`green`、`monochrome` で、「カレンダーの色」を選んだ予定はカレンダーの配色の名前（`monochrome` など）になる。有料版のラベル 8 種と任意の色の値は未確認である。テンプレートでは `class="label label--{event_color}"` のようにクラス名に使い、色ごとの見た目は CSS で付ける。値は `esc_attr()` を通し、クラス名に使えない文字を含む値は空にする。色の実際の値（16 進数）は返さないので、カレンダー本体と同じ色にしたいときは、カレンダーページの表示から採る。

### 区間

繰り返す部分と、条件を満たすときだけ出す部分は、開始タグ `{name}` と終了タグ `{/name}` で囲む。
この囲んだ範囲を**区間**と呼ぶ。

| 区間 | 出力するとき |
| --- | --- |
| `{events}…{/events}` | 今日の予定について 1 件ごとに中身を繰り返す。`limit` を指定したときは先頭から最大 `limit` 件 |
| `{has_events}…{/has_events}` | 今日の予定が 1 件以上ある |
| `{no_events}…{/no_events}` | 今日の予定が 0 件である |
| `{more}…{/more}` | `limit` を指定していて、今日の予定が `limit` 件を超える |
| `{holiday}…{/holiday}` | 今日が祝日である |

条件を満たさない区間は、中身ごと出力しない。
「ほか N 件」は `{more}ほか {more_count} 件{/more}` と書く。

名前の違う区間は入れ子にできる。
`<ul>` のような外枠を予定があるときだけ出すには、`{has_events}<ul>{events}<li>…</li>{/events}</ul>{/has_events}` のように、`{events}` を `{has_events}` の中に入れる必要があるためである。
予定ごとのプレースホルダーは、`{events}` の中にある別の区間の中にも書ける。

区間は、開始タグから、囲んでいる区間の中で最初に現れる同じ名前の終了タグまでとする。
このため、同じ名前の区間は入れ子にできず、内側の開始タグと外側の終了タグは文字のまま残る。
囲んでいる区間の外にある終了タグとは対にならないので、`{has_events}A{events}B{/has_events}C{/events}` のように交差した区間では、`{events}` と `{/events}` が文字のまま残る。
終了タグのない開始タグと、開始タグのない終了タグも、文字のまま残る。

### 置き換えの規則

- **知らない名前**：表にない名前（`{foo}`、大文字を含む `{Year}`、空白を含む `{ year }` など）は、置き換えずにそのまま残す。テンプレートに書いた CSS や JavaScript の波括弧（`.a{color:red}` など）を壊さないためである。名前を書き間違えても、ページに文字のまま出るので書いた人が気付ける。
- **区間の外の予定の値**：`{event_name}` などの予定ごとのプレースホルダーを `{events}` の外に書いた場合も、そのまま残す。空にすると書き間違いに気付けないので、知らない名前と同じ扱いにそろえる。
- **値の中の波括弧**：埋めた値は、もう一度置き換えの対象にしない。予定名に `{year}` と書かれていれば、`{year}` のまま出力する。

### エスケープ

プレースホルダーの値は、埋めるときに次のようにエスケープする。

- **テキストの値**：`{event_name}`、`{event_description}`、`{holiday_name}` は `esc_html()` を通す。日付、曜日、件数の値（`{year}` など）はプラグインが作る値だが、同じく `esc_html()` を通す。
- **URL の値**：`{event_url}` は `esc_url()` を通す。
- **予定名のリンク**：`{event_link}` は、予定名に `esc_html()`、URL に `esc_url()` を通して組み立てる。

値を書ける位置は次のとおりである。

- **要素の中身**：どの値も書ける。
- **引用符で囲んだ属性値**：`{event_link}` 以外の値を書ける。`esc_html()` は `"` と `'` も文字参照にするので、`title="{event_name}"` と書いても値が属性値の外に出ない。`{event_link}` は HTML 要素なので書けない。
- **URL の属性（`href`、`src` など）**：`{event_url}` と、日付、曜日、件数の値だけを書く。テキストの値は、`esc_html()` を通しても `javascript:alert(1)` のような文字列がそのまま残るので、`href="{event_name}"` と書くと予定名がリンク先として働く。
- **引用符で囲まない属性値、`<script>`、`<style>`、`onclick` などのイベント属性**：値を書かない。`esc_html()` ではこれらの位置で安全にならない。

説明に改行が含まれていても、`<br>` に変えずにそのまま出力する。
改行を表示に生かしたいときはテンプレート側の CSS で `white-space: pre-line` を指定する。
`<br>` に変えないのは、説明を属性値（`title` など）にも書けるようにしておくためである。

### kses の扱い

`unfiltered_html` 権限を持たない利用者が保存した本文は、保存時に kses を通り、`<script>`、イベント属性、`javascript:` の URL が取り除かれる。
プレースホルダーは kses を通っても残る（`href="{event_url}"` も残る）。

しかし、保存時の kses だけでは、区間を使ったテンプレートを安全にできない。
kses はタグを 1 つずつ調べるが、区間はあるタグの属性値の中で始まり、後ろのタグの中で終わることができる。
この区間を出力しないときや繰り返すときは、残った断片がつながり、kses が調べていないタグ（イベント属性を持つタグなど）ができる。
このため、埋めた後の出力にも、誰が書いたテンプレートでも `wp_kses_post()` を通す。
本文の投稿者（`post_author`）が `unfiltered_html` を持っていても省略しない。
投稿者と本文を最後に保存した人は一致しないためである。
たとえばマルチサイトでは `unfiltered_html` を持つのは特権管理者だけなので、特権管理者が作った投稿を編集者が更新すると、本文は保存時の kses を通るが投稿者は特権管理者のままになる。
同期パターン（`wp:block`）の中に置いたテンプレートも、描画中の `get_post()` は外側のページを返すので、投稿者ではパターンを書いた人を判定できない。
埋めた後の出力に必ず通すことで、これらの場合も断片がつながってできたタグが出力に残らない。

その代わり、kses が許さない要素（`<svg>` など）は、`unfiltered_html` を持つ利用者でもテンプレートに書けない。

組み込みのテンプレートには kses を通さない。
組み込みのテンプレートはプラグインが持つ文字列であり、利用者の入力を含まないためである。

URL の属性にテキストの値を書いた場合（`href="{event_name}"` など）は、`wp_kses_post()` が `javascript:` などの URL を取り除く。
ただし、これに頼らず、上の「URL の属性」の規則をテンプレートを書く人が守ることとする。

### the_content のほかのフィルタ

テンプレートは本文の一部なので、ショートコードを展開する `do_shortcode`（優先度 11）より前に、`the_content` のほかのフィルタを通る。

- **wptexturize（優先度 10）**：タグの外の文字が変わる（`"` が向きのある引用符になるなど）。タグの中の属性値は、`&` が `&#038;` になるだけで意味は変わらない。
- **カレンダープラグイン（優先度 10）**：`{{limited-calendar-<hash>}}` の形だけを置き換える。`{year}` は変わらない。
- **wpautop**：「カスタム HTML」ブロックの中身にはかからない。

どれもプレースホルダーを変えないので、対処しない。
埋めた値はショートコードの出力なので、上のフィルタを通らない。

### テンプレートの出力

- **外枠**：埋めたテンプレートをそのまま出力し、プラグインの要素で包まない。テンプレートを自分の HTML の中（グリッドの 1 マスなど）に置いたとき、プラグインが足した要素で配置が崩れないようにするためである。
- **本文の列への揃え**：本文の列に揃えるには、テンプレートのいちばん外側をブロック要素（`<div>` など）にする。
- **CSS**：プラグインの CSS を読み込まない（「CSS」の節）。
- **予定ごとのリンク**：`{event_link}` と `{event_url}` で予定ごとのリンクを出せる。ただし、テンプレート全体を `<a>` で囲む場合は、中にリンクを書かない。プラグインはこれを検査しないので、テンプレートを書く人が守る。
- **テンプレートの中のショートコード**：要素の中身に書いたショートコードは展開せず、文字のまま出力する。属性値に書いたショートコードは、プラグインがテンプレートを受け取る前に、コアの `do_shortcodes_in_html_tags()` が展開する。プラグインはプレースホルダーを埋めた後にショートコードを展開しないので、予定名に書かれた `[…]` がショートコードとして動くことはない。
- **hash の誤りとカレンダープラグインの停止**：閲覧者には何も出さず、管理者にだけ原因を出す（「管理者向けの表示」の節）。テンプレートは出力しない。
- **取得の失敗**：予定が 0 件として扱うので、`{no_events}` の区間が出る。

### テンプレートの例

「カスタム HTML」ブロックに次のように書く。

```html
[today_schedule hash="pocevents" limit="3"]
<div class="my-today">
  <time class="my-today__date" datetime="{date}">{year}年{month}月{day}日（{weekday}{holiday}・祝{/holiday}）</time>
  {has_events}<ul class="my-today__events">
    {events}<li>{event_link}<span class="my-today__desc">{event_description}</span></li>{/events}
  </ul>{/has_events}
  {more}<p class="my-today__more">ほか {more_count} 件</p>{/more}
  {no_events}<p class="my-today__none">本日の予定はありません</p>{/no_events}
  <a class="my-today__all" href="/calendar/">カレンダーを見る</a>
</div>
[/today_schedule]
```

2026 年 9 月 19 日（土曜、祝日でない）に、予定が「休館日」（リンク `https://www.yahoo.co.jp`、説明なし）の 1 件だけある場合は、次の HTML を出力する。

```html
<div class="my-today">
  <time class="my-today__date" datetime="2026-09-19">2026年9月19日（土）</time>
  <ul class="my-today__events">
    <li><a href="https://www.yahoo.co.jp">休館日</a><span class="my-today__desc"></span></li>
  </ul>


  <a class="my-today__all" href="/calendar/">カレンダーを見る</a>
</div>
```

出力しなかった区間の行は、空白だけの行として残る。
説明のない予定では `<span class="my-today__desc"></span>` が空のまま残るので、隠すには CSS の `:empty` を使う。

#### 開館時間を出す例

「本日は 開館日」と「開館時間 10:00 – 18:00」のように、その日の状態と時間を出す場合は、状態を予定名に、時間を説明に登録する。
たとえば予定名「開館日」、説明「10:00 – 18:00」と登録し、次のテンプレートを書く。

```html
[today_schedule hash="<hash>" limit="3"]
<div class="today-status">
  <p class="today-status__labels">本日は{events}<span class="today-status__label today-status__label--{event_color}">{event_name}</span>{/events}</p>
  {has_events}<p class="today-status__hours">開館時間{events}<span class="today-status__time">{event_description}</span>{/events}</p>{/has_events}
</div>
[/today_schedule]
```

説明は登録した文字のまま出るので、時間の書式は登録する人がそろえる。
状態ごとの色は、カレンダープラグインで予定に付けたラベルの色をそのまま使う。
`{event_color}` をクラス名に入れ、`.today-status__label--green` のように色ごとの CSS を書く。
説明のない予定の `today-status__time` は空になるので、`:empty` で隠す。
動く例は `docs/samples/top-museum.html` にある。

## 取得とキャッシュ

今日を含む月の 1 か月分だけを、`rest_do_request()` でカレンダープラグインの REST（`GET /8bit-limited-calendars/v1/calendar`、`hash`、`year`、`month` を指定）から取る。
`year` と `month` は、サイトのタイムゾーンでの今日から求める。
応答の `calendars` の先頭要素の `calendar` から、`date` が今日と一致する要素を取り出す。

PoC は表示範囲にかかる月をすべて取っていたが、今日の 1 日分しか使わないので今月だけにした。

### キャッシュ

月ごとの応答を transient に 5 秒保存する。

- **キー**：`wp_calendar_today_<hash の MD5>_<YYYYMM>`（例：`wp_calendar_today_04c0cadd330c036972d181946e8d0e89_202609`）。hash には任意の文字が入りうるので、キーに使える長さと文字に収めるため MD5 にする。
- **保存する値**：REST の応答本文（`calendars` を含む配列）。
- **保存しない応答**：取得に失敗した応答に加え、hash の誤り（空の `calendars`）も保存しない。カレンダーを作り直したときや hash を直したときに、すぐ反映させるためである。

予定を登録してからバッジに反映されるまで、最大 5 秒かかる。
すぐに反映させたいときは、`wp transient delete` で消す。

PoC からの変更点は、キーの接頭辞をプラグイン名に合わせて `top_schedule_` から `wp_calendar_today_` に変えたことである。

### 取得の失敗

ステータスが 200 でない応答、エラー、例外は、今日の予定がない（0 件）ものとして扱い、`error_log()` に記録する。
取得の失敗は hash の誤りと違って一時的なものである場合が多く、管理者に原因を出す対象にはしない。

例外を捕捉するのは、不正な年月でカレンダープラグインが例外を投げるためである。
このプラグインは自前で計算した正しい年月しか渡さないが、内部呼び出し（`rest_do_request()`）で例外が漏れるとトップページ全体が致命的エラーになるので、念のため捕捉する。

## 管理者向けの表示

次の 3 つは、閲覧者には何も出さず（ショートコードは空文字を返す）、`manage_options` 権限を持つユーザーにだけ原因を短く表示する。

- **カレンダープラグインの停止**：`LimitedCalendar8bit` クラスが存在しない。
- **hash の未指定**：`hash` 属性が空である。
- **hash の誤り**：REST がステータス 200 で空の `calendars` を返した。

管理者向けの表示は `<div class="wp-calendar-today wp-calendar-today--notice">` の中に、原因と「管理者にだけ表示しています」の旨を出力する。
テンプレートの有無にかかわらず、この形で出力する。

## CSS

プラグインの CSS（`assets/css/wp-calendar-today-plugin.css`）は、組み込みのテンプレートと管理者向けの表示を出力するときだけ読み込む。
利用者のテンプレートはプラグインのクラスを使わないので、読み込んでも使われないためである。
ショートコードの展開は `wp_head` の後なので、そこで `wp_enqueue_style()` を呼ぶと、WordPress はフッターで出力する。

## 日付の鮮度

日付はサーバー側で HTML に書き込む。
本番でページキャッシュ（キャッシュ用プラグインや CDN）を使うと、日付が変わった後も前の日のバッジが出続けるおそれがある。
その場合は、ブラウザ側で日付を入れ、今日の予定を REST から取る方式に変える。
